# GLOSSARY.md pattern

Keep a small, living `GLOSSARY.md` at the repo root: project-specific jargon
explained in plain language, as it comes up in code, PRs, and reviews.

- Not a formal spec — a running list for learning, updated incrementally.
- Add a term whenever one comes up in review or conversation that's worth
  remembering (a coined name for a pattern, a domain concept, an internal
  abbreviation) — don't try to front-load it with every term up front.
- Each entry: the term, then one or two sentences of plain-language
  explanation, ideally with a pointer to where it's implemented (a function
  or constant name) if that helps ground it.

Cheap to start, cheap to maintain, and it gives new contributors (human or
agent) a single place to look up a project's private vocabulary instead of
re-deriving it from code.
